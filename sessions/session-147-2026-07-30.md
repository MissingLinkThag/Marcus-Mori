## MCP Gateway Design — 5 Architecture Decisions (Locked)

Full design doc written and shared in Mean Girls channel for Andrew's review.

| # | Question | Decision |
|---|----------|----------|
| 1 | Identity resolution | Option C + verification key. Agent sends X-Agent-ID + X-Agent-Key + user OAuth token. Two channels, both verified. |
| 2 | Gateway-to-WALDO auth | Single gateway key. Gateway is a registered GovernedComponent. Agent/user identity in payload. |
| 3 | Second MCP for telemetry | No. Gateway records execution. Agents POST additional telemetry directly to WALDO API. |
| 4 | Kindra Console integration | Andrew's call. Recommendation: Kindra talks to WALDO directly, gateway for MCP agents only. |
| 5 | Deployment topology | Separated from day one. Gateway = own host. MCP servers = own host. Gateway is the ONLY entry point — MCP servers accept connections from gateway IP only. |

Defense model: v1 = key + network + audit (sufficient). v2 = anomaly detection (once baseline traffic exists).

Caching: bootstrap 5min TTL, user clearance 5min TTL, classification NO CACHE (live calls only).
