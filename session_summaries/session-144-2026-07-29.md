### Architecture Design — WALDO v2

The bulk of the session was a deep architecture design for WALDO's next generation. Triggered by Pete's feedback (kill "Dashboard", revamp Skills to match Yggdrasil), the InQTel demo request, and Marcus's instinct that the product wasn't "all the way there yet."

**Five-Layer Skills Architecture:**
1. Universal Skill Registry (5 types: integration/procedural/analytical/creative/administrative, structured definitions, constraints, surface mappings, governance fields, verification cadence, source tracking)
2. Skill-Agent Authorization Matrix (many-to-many, 4 autonomy levels: execute_freely/execute_and_report/propose_only/disabled, conditions, expiry)
3. Skill Execution Telemetry (per-skill execution records linked to sessions, authorizations, users)
4. Skill Performance Attribution (alignment failure modes: none/prompt_adequacy/agent_execution/scope_creep/tool_failure, per-skill trust decomposition)
5. Skill Lifecycle Management (discovery, ingestion, distribution, drift detection — WALDO as source of truth)

**MCP Server — Universal Integration:**
- Microsoft Copilot already supports custom MCP servers (confirmed by Marcus via Microsoft docs)
- WALDO as MCP Server: one protocol, every enterprise AI platform connects
- MCP tools: waldo_authorize_skill, waldo_get_authorized_skills, waldo_classify_data, waldo_report_execution, waldo_check_user_clearance, waldo_get_constraints, waldo_report_error
- Gateway redesign merges INTO MCP — authorization + classification as MCP tools

**Agent Governance Contract:**
- Mandatory protocol block for every governed agent's system prompt
- Startup: pull authorized skills from WALDO
- Before execution: check authorization + clearance + classification
- On completion: report via telemetry
- On violation: deny, log, do not attempt

**Telemetry Redesign:**
- Session tracking (group events into user requests)
- Structured input/output (replaces payload_json blob)
- Event taxonomy (controlled vocabulary)
- Parent-child event chains
- Data lineage / provenance
- Per-skill, per-session cost attribution

**Gateway Redesign:**
- Split into classification_service + authorization_service
- 4-step evaluation: data classification → skill authorization → routing → continuous monitoring
- Merges into MCP Server as tool implementations

**Deeper Gaps Found (second pass):**
- Agent State Snapshots (reconstruct complete agent state at any timestamp)
- Agent Relationships / Dependency Graph (blast radius, cascading trust)
- Data Flow Boundaries (clearance chain enforcement between agents)
- Intent Validation (pre-execution reasonableness checks)
- Provenance Chains (full trace from request through agents/models to output/decision)
- Organizational Context (team/project/business process scoping)
- Continuous Compliance Monitoring (testable assertions, auto-evaluated by RANDALL)
- Compliance Evidence Model (link requirements to proof)
- Simulation / What-If analysis
- Trust Score Profiles (type-aware scoring — agents scored differently than policies)
- Trend Analysis (trajectory detection)
- Automated NC Chaining (compliance failure → NC → flag → management review)

**Clean Layered Architecture:**
- Layer 0: Foundation (FROZEN — protect all existing working code)
- Layer 1: Structural Extensions (new models only, no existing code changes)
- Layer 2: Telemetry & Execution (redesigned, depends on Layer 1 Skills)
- Layer 3: Governance Engine (MCP + Gateway + Contract, depends on L1+L2)
- Layer 4: Intelligence (Trust + RANDALL + Alignment + Compliance, depends on all below)
- Layer 5: Experience (Panorama + Reporting + Simulation + Connectors, read-only)

Rule: dependencies only point DOWN. Each layer is additive. No existing functions rewritten. No existing tests broken.
