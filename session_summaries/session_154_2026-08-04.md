## Design Decisions
- **Wizard over CLI** — interactive browser wizard chosen over `flask onboard` CLI. CLI is ops convenience; product experience should be the wizard. HELM can POST to the same endpoint programmatically for automated deploys.
- **Guided onboarding over documentation** — instead of a Getting Started guide, built an in-app guided path that walks users through real actions. By step 6 they have a component, trust score, CR, and baseline — their instance is populated with their actual data.
- **No model needed for progress tracking** — onboarding progress determined by querying real tables (GovernedComponent.count(), TrustScoreSnapshot.count(), etc.), not by a separate progress tracker. Only addition: `onboarding_complete` boolean on User model for dismiss state.
- **HELM unchanged for first customer** — SOP-013 applied. Scale features (automated provisioning, feature flags, multi-instance dashboard) are post-customer-20 concerns, not customer-2 concerns.

## FRED Lessons
1. **Max ~50 files per spec** — FRED drops files beyond this threshold
2. **Explicit preservation rules required** — "Do NOT delete any existing file" must be stated, not assumed
3. **Never imply a directory should be rebuilt** — phrases like "Phase 1 missed the templates" cause FRED to wipe and recreate rather than add
4. **Phase ordering matters** — restore before modify, always
